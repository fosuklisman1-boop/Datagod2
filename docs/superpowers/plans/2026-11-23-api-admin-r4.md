# API Admin Console (Release 4) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn `/admin/api-keys` into a tabbed console and add developer profiles with pause, pause per service, a public status page, announcements and a business report, without touching the v2 contract or any price.

**Architecture:** One additive migration (three tables, nine functions). The request path reads pauses from a 10 s per-instance snapshot (no query per request). Admin logic lives in `lib/api-v2/admin-console/` behind thin routes; public status and announcements are cached routes read by client components so the docs stay static.

**Tech Stack:** Next.js 15, TypeScript, Supabase Postgres, Vitest, PGlite.

**Spec:** `docs/superpowers/specs/2026-11-23-api-admin-r4-design.md`. Read it with this plan; section numbers below (`§`) refer to it.

## Global Constraints

- Work only in `B:/worktrees/api-rebuild` on branch `feat/api-admin-r4`. Never switch branches. No `git stash`, `checkout`, `reset` or `clean`. Stage named files only.
- Edit/Write only for code. Never sed (tell any helper).
- Failing test first, shown red, then green. Run `CI=1 npx vitest run --maxWorkers=2 <paths>` from the uppercase drive path `B:/worktrees/api-rebuild`.
- `route.ts` files export only HTTP handlers and route config (`dynamic`, `maxDuration`, `revalidate`). All logic goes in `lib/`.
- Deploy order: the migration is applied BEFORE the code. Old code must keep working on the new schema (nothing reads the new objects). The hot path must not break if the code ships first: a missing pause table reads as "nothing paused" (§6.3).
- v2 success and error envelopes do not change. The only new responses are 403 "API access paused by Datagod" and 503 with the service message (§6).
- The hot path adds no query per request (§6.2). Only `lib/api-v2/controls.ts` reads the new tables on the request path.
- Every admin method calls `verifyAdminAccess`. Every admin WRITE also needs a real admin user id; the CRON_SECRET path gets 403 (R33), enforced in the route and again in the lib function.
- Never mention the cost table or its column name outside `migrations/` (the `package-costs.guard.test.ts` allow-list is not changed). TypeScript sees only `cost_total` and `costed_*`.
- Never guess a cost: "no cost set" when `costed_orders = 0`; partial rows say so.
- Logs, errors and audit rows carry no key, hash, phone or email. `error_reason` stays a closed slug set; the admin's service message is never logged.
- No SMS or email sending. Announcements are display only.
- Migration number: `0196`. Re-check with `git ls-tree` on every ref before Task 1 and again before applying; record the result in the commit body.
- Migration has a code-built self-rolling-back selftest and PGlite tests, as `0195` (`lib/api-v2/migration-0195.test.ts`, `migration-0195-run.ts`).
- UI: navy `--primary`, dark mode, works at 500 px, `lg:` multi-column on every new view (`docs/ui-conventions.md`).
- Commit trailer on every commit: `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- No production SQL, push, or deploy without the final task's gates. The 9 known order-health failures are the only accepted red tests.
- Placeholder-env `next build` must pass before any push.
- Fresh reviewer gates: Task 1 (migration) and Task 3 (request path). Findings are fixed with a failing test first.

## Review Focus

1. A paused developer uses a second key, a test key or `X-API-Key`: still 403. An unpaused developer pays no extra query and is never blocked by a controls outage that has a recent snapshot. (Tasks 2, 3)
2. The code ships before the migration: every request still works, nothing is paused, no 503 storm. (Tasks 2, 3)
3. The CRON_SECRET bearer cannot pause, resume, switch a service or post an announcement, and nothing is audited. (Tasks 1, 4)
4. The public status route leaks no per-user or per-count data and survives a `?x=random` flood with one query pair per instance per minute. (Task 6)
5. A name, announcement or service message containing `<script>`, `=cmd|...` or control characters is harmless on the page, in the banner and in the CSV. (Tasks 4, 6, 9, 10)
6. The report never shows a profit for an order whose package has no cost row, and the totals match `api_v2_admin_stats` revenue for the same window. (Tasks 1, 5, 10)
